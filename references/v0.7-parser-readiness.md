# v0.7 Parser-Readiness Policy

v0.7 introduces parser-readiness review, not a production parser.

## Scope

- Fixture-first only.
- Local snapshots, fixtures, candidate packages, review decisions, quality scores and quarantine manifests may be inspected.
- Production iXBRL parsing is not claimed.
- Live extraction is not enabled.
- Complete 10-K / 10-Q parsing is not in scope.

## Required Checks

- Candidate provenance includes source locator, concept QName, context, unit, period, dimensions and source status.
- Mapping records include mapping version, taxonomy version and relationship metadata.
- Review decisions link back to candidate IDs.
- Promotion or quarantine outputs link back to review decisions and quality scores.
- Dry-runs link back to normalized CSV or quarantined CSV manifests.
- Report packets must link back to packet, dry-run and audit references.

## Default Result

`production_parser_ready: No`

Reason: fixture-first prototype; production parser requires separate implementation, full filing coverage, rendering reconciliation, taxonomy drift controls and human approval.
