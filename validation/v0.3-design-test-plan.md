# v0.3 Design Test Plan

## 1. Scope

本计划定义 v0.3 future implementation 的 fixture、contract、provenance、freshness、cache、failure 和 security tests。它不包含 live adapter 或网络测试代码。

## 2. Test Fixtures Needed

| Fixture | Purpose | Required evidence |
|---|---|---|
| MRVL fixture | AI networking/custom silicon、special items、FCFE approximation | Filing/release snapshots, market snapshot, GAAP caution |
| NVDA fixture | Marketable securities、split-adjusted shares、AI/data-center categories | 10-K/10-Q, split basis, locked securities note |
| AVGO fixture | Acquisition accounting、software/semiconductor mix、debt | 10-K/10-Q/reconciliation, goodwill/intangibles |
| Stale market data fixture | Prevent stale current valuation | Old timestamp and completed newer session |
| Source conflict fixture | Preserve multiple values and resolution | Filing vs release/vendor mismatch |
| Missing field fixture | No blank/zero fabrication | Missing normalized earnings or segment metric |
| Restatement fixture | Version lineage and invalidation | Original filing plus amendment |
| Split-adjusted share count fixture | Prevent per-share mismatch | Pre/post split and company-restated history |

Additional recommended fixtures:

- Currency mismatch.
- Unit mismatch.
- Ticker/CIK mismatch.
- Secondary-page timestamp missing.
- Unsupported bank/REIT company type.

Fixtures must be local, small, license-safe and deterministic.

## 3. Contract Tests

- Adapter metadata contains mode, key requirement, source allowlist and prohibited actions.
- Output includes only evidence package fields defined by `adapter_contract_schema.md`.
- Output rejects `investment_conclusion`, `recommendation`, `target_price`, `research_status`, broker or order fields.
- Missing evidence may produce zero normalized paths without failing the evidence package.
- Errors use stable code, severity, stage and affected fields.
- Adapter cannot mutate a source or existing raw snapshot.

## 4. Provenance Tests

- Every populated normalized field has a provenance record.
- Every provenance `source_id` resolves to source manifest.
- Every retained source resolves to raw snapshot and checksum.
- TTM bridge records all components and formula.
- Unit scaling records conversion factor.
- Analyst assumptions cannot be verified/company-disclosed.
- Secondary market values remain indicative unless cross-checked.
- AI/data-center fields preserve disclosed category names.

## 5. Freshness Tests

- Daily market snapshot includes timestamp, timezone and session.
- Stale current price is rejected for current valuation.
- Historical stale filing remains usable for its historical period.
- New amendment supersedes old active filing.
- Transcript freshness is tied to event, not current market date.
- Analyst assumption past review_due generates warning.

## 6. Cache Tests

- Raw snapshot cannot be silently overwritten.
- Same bytes can be recognized by checksum without losing retrieval event.
- New retrieval creates a new version/path.
- Changed input invalidates dependent normalized and derived status.
- Cache fallback preserves original retrieved_at and stale status.
- Restricted evidence uses metadata-only retention and is not committed.

## 7. Failure Mode Tests

| Test | Expected behavior |
|---|---|
| Ambiguous ticker | Blocking; no normalized input |
| CIK mismatch | Blocking identity error |
| Missing filing | Explicit unresolved fields; no future-data leakage |
| Unit mismatch | Stop affected normalization |
| Currency mismatch | No silent conversion |
| Split mismatch | Stop per-share bridge |
| Source conflict | Preserve all sources and resolution state |
| Missing reconciliation | No invented normalized earnings |
| Segment change | Comparability warning and recast preference |
| Acquisition break | Reported vs organic/pro forma distinction |
| Network/auth/rate limit | Structured future error, no secret logging |
| Unsupported company type | Partial/no support with explanation |

## 8. Security Boundary Tests

- Static scan rejects network modules unless explicitly approved implementation phase begins.
- No credential value in source manifest, snapshot manifest, logs or errors.
- No `os.environ` secret reads in design phase.
- No browser automation, subprocess or shell execution.
- No broker SDK, order, trade or portfolio action.
- No adapter output field representing recommendation or investment conclusion.
- Evidence output paths remain under approved local root.

## 9. Regression Tests Against v0.2.x Tools

For each MRVL/NVDA/AVGO fixture:

1. Produce normalized financials CSV.
2. Produce assumptions JSON only from explicit input plus analyst assumptions.
3. Produce peer comps CSV with market snapshot provenance.
4. Produce valuation CSV with market timestamp/session.
5. Run all four existing scripts.
6. Compare required sections, units and warnings.
7. Confirm no normalized value appears without provenance.

The v0.2.x scripts remain unchanged local calculators; adapter tests must conform to them rather than bypass them.

## 10. Acceptance Criteria for v0.3 Implementation

Implementation may begin only when:

- All design schemas are approved.
- No unresolved High/Medium design issue exists.
- The first adapter scope is explicitly approved by the user.
- First adapter is no-key, official-source and read-only.
- Local fixtures exist before live integration.
- Contract tests prove no investment-conclusion output.
- Provenance tests cover every populated normalized field.
- Freshness/cache/failure behavior is deterministic.
- Security tests exclude credentials, broker and trading behavior.
- Existing 16-case calculation regression remains green.

Recommended first implementation candidate: a narrow no-key official filing adapter that writes raw filing evidence and manifests for a user-specified CIK/form/accession, without market data or authentication.
