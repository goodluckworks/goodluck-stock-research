## 4. Field Scope Review

The first scope is limited to nine consolidated GAAP fields:

- Revenue.
- Gross profit.
- Operating income.
- Net income.
- Operating cash flow.
- Capital expenditure.
- Cash and equivalents.
- Total debt.
- Diluted weighted-average shares.

The design avoids scope creep:

- No segment, AI-only, Non-GAAP, normalized earnings or valuation extraction.
- No gross-profit reconstruction when not explicitly reported.
- No TTM or cross-filing bridge.
- No marketable securities/net-debt derivation.
- Missing or ambiguous fields remain unresolved.

Field-specific safeguards cover capex sign, cash basis, debt double counting,
net-income attribution and weighted-average diluted share period/split basis.

| Taxonomy-version drift | Medium | Versioned mapping records and explicit supported taxonomy years. | Addressed as implementation gate |

## 6. Human Review Gate Review

The design separates:

```text
raw snapshot
  -> extraction candidates (draft_extracted_unreviewed)
  -> human review records
  -> explicit promotion
  -> approved local normalized input
```

Extraction cannot directly invoke v0.2.x scripts. Approval requires checksum
integrity, approved mapping version, resolved context/unit/sign/scale and one
final decision for every populated field. Adjustments retain both extracted and
approved values. Rejections and unresolved values cannot enter normalized
files.

This gate is sufficient for a prototype design. Implementation still requires
machine-validatable candidate/review formats and tests proving that promotion
cannot bypass review.

## 7. Real Case Applicability

### MRVL

- Tests extension/fallback revenue mapping and consolidated versus AI/data-center narrative.
- Tests GAAP special items without auto-normalization.
- Tests capex concept and sign behavior.

### NVDA

- Tests split-restated diluted weighted-average shares.
- Tests cash versus marketable securities boundary.
- Tests dimensions and consolidated versus product/data-center facts.

### AVGO

- Tests acquisition-driven presentation and extension concepts.
- Tests semiconductor/software dimensions versus consolidated fields.
- Tests current/noncurrent debt components and double-count prevention.

The three cases are appropriate fixture targets, but none proves support for
banks, insurers, foreign issuers or other excluded entity types.

|---|---|---|---|
| A single tag list could encourage first-match extraction. | High | Added ordered context, unit, statement and reconciliation gates; first-match selection prohibited. | Resolved |

No unresolved High design issue remains. Medium open decisions block implementation
approval until the user chooses the prototype mode, but they do not block this
scope/design release.

## 9. Recommendation

- Ready for v0.3.3 extraction prototype: No, pending explicit user approval and
  decisions listed below.
- Recommended prototype mode: Offline, fixture-first parser that reads one
  existing checksum-verified raw snapshot and emits draft candidates only.
- Required user decisions:
  - Inline XBRL HTML, filing instance files, or both.
  - Approved taxonomy years and exact mapping QNames.
  - Extension relationship requirements.
  - Whether `total_debt` remains required in the first prototype.
  - Capex scope, including capitalized software.
  - Materiality thresholds for prior-period review.
  - Separate promotion command and reviewer identity approach.
- Risks:
  - Extension semantics and taxonomy drift.
  - Context/dimension mistakes.
  - Amendment and restatement lineage.
  - Unit, sign and share-split errors.
  - Human reviewers treating low-confidence candidates as facts.
