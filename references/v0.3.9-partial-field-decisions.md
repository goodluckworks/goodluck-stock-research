# v0.3.9 Partial-Field Decisions

## 1. Purpose

v0.3.9 makes partial fictional sandbox output explicit and auditable. A sandbox CSV may contain only the EXMP fields that passed review, while omitted fields remain blank and are explained through downstream impact metadata.

## 2. Field Statuses

- `approved`: reviewer accepted the extracted value.
- `adjusted`: reviewer supplied an approved adjusted value.
- `rejected`: reviewer rejected the candidate; it must not populate CSV.
- `unresolved`: evidence is insufficient; it must not populate CSV.
- `missing`: no approved value is available.
- `unsupported`: not supported by the current sandbox mapping or downstream script.
- `blocked`: blocked by policy or safety gate.
- `not_required_for_this_script`: metadata or fields not required for the current ratio dry-run.

## 3. Ratio Calculator Minimum Run Fields

`ratio_calculator.py` can run a partial sandbox when the CSV has these required metadata and baseline fields:

- `period`
- `currency`
- `amount_unit`
- `per_share_unit`
- `basis`
- `revenue`
- `source`
- `source_date`
- `source_status`

Other missing financial fields make specific ratios unavailable; they are not filled with zero.

## 4. Rules

- Missing or unresolved fields must remain blank.
- Rejected, unresolved and blocked fields must never enter populated CSV values.
- The CSV manifest must list `populated_fields`, `omitted_fields`, `unresolved_fields`, `blocked_fields` and `downstream_impact`.
- Ratio dry-run output must include available ratios, unavailable ratios, missing inputs and a caution banner.
- MRVL, NVDA and AVGO remain blocked from CSV generation and dry-run.

## 5. Acceptance Criteria

- EXMP full field sandbox passes.
- EXMP partial field sandbox passes.
- Missing fields are not zero-filled.
- Unresolved fields are not populated.
- Downstream ratio impact is visible in manifest and reports.
- Real ticker CSV and dry-run attempts are blocked.
